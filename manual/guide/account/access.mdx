## 同一应用的不同入口

| 使用入口 | 从哪里核对 | 首先检查 |
| --- | --- | --- |
| 已登录成员 | 「我的 → 个人信息」确认当前团队；在「聊天」开新会话 | 成员是否有效、应用是否已发布并开放、资源和模型授权 |
| 分享入口 | 应用的发布配置 | 是否是目标应用的有效发布入口、分享配置及其执行所需权限 |
| API 密钥 | 「我的 → API 密钥」与应用发布配置 | 密钥是否有效、签发者是否仍为有效团队成员、应用绑定及调用范围 |

一个账号在不同团队可以承担不同角色。分享链接和密钥按照各自的使用范围生效；从登录态能使用某个应用时，仍需单独验收分享或 API 调用。平台管理员的管理能力在受控入口执行。签发密钥前先确认实际所需范围，再选择对应凭据。

## 用测试账号验证一次分配

1. 管理员在当前团队选择一个普通成员、一项具体资源和一项操作，例如只查看《差旅示例》知识库，保留同文件夹的其他资源作对照。
2. 在目标资源的「权限」配置协作者。使用另一浏览器会话以该成员登录，确认能进入目录、看到授权目标，同时检查对照资源及编辑按钮。
3. 若需要开放聊天，从发布后入口确认引用和模型实际可用。若还使用分享或 API，从该入口独立验证。
4. 撤销授权后让成员刷新权限相关页面并复验。角色调整、移出团队和失去创建 API 密钥权限都可能使已有调用无法继续。管理员可在「团队管理」检查审计和登录会话。

## 看见登录或授权错误时

先定位失败入口：登录态查当前团队和成员状态；分享查发布配置；API 查密钥和其绑定的团队、签发成员、目标应用。再逐层核对资源权限与模型权限。必要时保存请求时间、入口类型和错误提示供管理员定位，交接时使用脱敏的错误信息。
