## 从结果倒查

在「知识库 → 搜索测试」输入固定题目。用一条有明确答案的问题和一条资料外的问题分别测试。例如「差旅报销期限是多少？」和「餐补一天多少钱？」。点击结果查看正文、分数和对应来源，确认正例包含正确期限，反例没有可作为答案的证据。

## 一次只改一个参数

![搜索配置中的混合检索、RRF 开关和结果重排](./assets/search-options.png)

| 控制项 | 调整时看什么 |
| --- | --- |
| 全文检索 | 核对缩写、编号、条款原词能否被找回 |
| 语义检索 | 用改写问题验证能否找到相同事实，检查索引模型是否可用 |
| 混合检索 | 同时覆盖原词和相似表达。若开启 RRF，按候选排名融合；查看结果排序，不把融合排序理解成单路相似度 |
| 相关度与引用上限 | 前者影响保留门槛，后者控制送给下游的文字预算。分别比较过宽、过窄的结果 |
| 重排 | 用相同查询比较前后顺序，开启前确认重排模型授权和可用 |
| 问题优化或关键词展开 | 用短问题、承接上轮或包含专有名词的题比较变化。检查展开是否引入无关范围 |
| 集合或标签过滤 | 需要限定某个版本、部门或类型时先配范围，再检查结果是否来自允许的集合 |

新建应用、节点和检索测试使用当前默认参数。已有应用可能保存了不同值。把验收时使用的知识库、范围和参数，分别核对到[对话 Agent](../agent/knowledge.mdx)或[工作流节点](../agent/workflow/nodes/dataset_search.mdx)。

## 用差旅样例确认命中

1. 将[快速上手](../quick-start.mdx)的 `差旅演示.txt` 导入，等「数据集」的处理完成后再测试。打开文件，先确认切片包含「15 个自然日」。
2. 在「搜索测试」问「出差结束后多久提交报销？」。示例用混合检索、最低相关度 0.2、未开启重排。结果区可核对测试参数、向量与全文召回条数以及最终保留的片段。打开结果核对文件名和正文中的时限。
3. 如果有召回条数但结果区为空，把同一个问题和同一份资料保留下来。先用原文词「差旅审批记录」切换到全文检索核对索引，再回到原配置单独调整最低相关度做对照。用有依据和无依据的题各复测一次，再决定业务配置。

混合检索中，同一片段同时被向量和全文召回时，如果它带有低于门槛的向量分数，仍可能被过滤。纯全文检索且未启用重排时，可用于核对这类情况。

## 如何判断问题出在哪一段

1. **无结果**：确认团队、库、过滤范围、训练状态和查询模型。用原文关键字试一遍，再看阈值。
2. **命中但上下文不全**：查看该段附近正文，检查分块策略、父子上下文和引用预算。先核对事实能否在正文中找到。
3. **检索正常但回答不对**：确认正式应用拿到这些引用，检查节点连线、提示词、保存及发布版本。用普通成员账号再试一次。
4. **前后结果不一致**：记录资料版本、配置和样本问题，避免在调整参数的同时切换模型或更新语料。
